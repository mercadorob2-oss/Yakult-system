Borrow Items Portal

Three additions to the desktop Borrow Items dashboard: a department-level requester, an IsBorrowable flag on items, and a pick-from-list popup that replaces retyping or rescanning a serial number.

Two constraints in the current schema shape everything below:

  • dbo.BorrowLog.BorrowedByEmpId is NOT NULL — a specific employee is always required, there's no way to borrow "for a department" in the abstract.
  • dbo.Item has no notion of borrowability — anything with a SerialNumber can be borrowed if someone knows it, which is also the only way to find it (type or scan).
01

Department-level requester

Let a borrow be attributed to a department as a whole, for cases like "IT borrowed this projector" where naming one employee doesn't fit.

UI change

Add a toggle next to the existing borrower cascade, following the same radio-button idiom already used for rbBorrowEmpAddNew / rbBorrowEmpListed — don't introduce a new control pattern for this.

Database change schema

Not a pure additive migration — it loosens a NOT NULL constraint, so call this out explicitly in review. Check no report or query already assumes BorrowedByEmpId is never null before merging.

DB Migration_BorrowLog_NullableRequesterEmp.sql
IF EXISTS (
    SELECT 1 FROM sys.columns
    WHERE object_id = OBJECT_ID('dbo.BorrowLog')
      AND name = 'BorrowedByEmpId' AND is_nullable = 0
)
BEGIN
    ALTER TABLE dbo.BorrowLog ALTER COLUMN BorrowedByEmpId INT NULL;
END
GO

IF NOT EXISTS (
    SELECT 1 FROM sys.check_constraints
    WHERE name = 'CK_BorrowLog_RequesterPresent'
)
BEGIN
    ALTER TABLE dbo.BorrowLog ADD CONSTRAINT CK_BorrowLog_RequesterPresent
        CHECK (BorrowedByEmpId IS NOT NULL OR BorrowedByDeptId IS NOT NULL);
END

Note: BorrowedByDeptId / BorrowedByDeptName already exist and are already nullable — only BorrowedByEmpId needs to move.

Code changes new logic, existing files

  • Repositories/BorrowItemsRepository.cs — BorrowAsync(...) (~line 619): change signature to accept int? borrowedByEmpId plus the department fields, and require exactly one identity to be present before inserting.
  • Forms/BorrowItemsDashboard.cs — add the toggle described above; wire it to disable/clear cboBorrowEmp.
  • Forms/BorrowItems/ConfirmBorrowDialog.cs — BorrowConfirmationModel.BorrowedBy needs a department-only display branch.
  • Decide, and note in the PR, whether returns need the same treatment — ReturnedByEmpId is already nullable, so likely UI-only parity is needed there.
Implemented: the toggle lives in Wpf/BorrowItems/WpfBorrowTransactionWorkspace.cs (_borrowDeptOnlyCheck), not the legacy cboBorrowEmp panel in Forms/BorrowItemsDashboard.cs — that panel is kept only as a hidden backing store for the visible WPF borrow card. BorrowFormEventArgs got a new BorrowForDepartmentOnly flag; BorrowItemsRepository.BorrowAsync now takes int? borrowedByEmpId plus optional borrowedByDeptId/borrowedByDeptName, and requires exactly one identity. BorrowLogRow.BorrowedByEmpId is now int? — every call site that fed it into FindCompanyIdByEmpId/SelectCompanyDeptEmp/SelectEmployee on the Return side needed .GetValueOrDefault(). Migration: Migration_BorrowLog_NullableRequesterEmp.sql (also mirrored into Tables/BorrowLog.sql). Returns were left as UI-only parity per the open decision above — no schema/repo change was needed since ReturnedByEmpId was already nullable and anyone can return a department-borrowed item.
02

IsBorrowable on items

An explicit switch so items that wouldn't normally circulate — spare hardware, demo units — can still be marked available for temporary borrow.

UI change — Items Page

Edit Item — Projector (Epson EB-X06)
Hardware — Peripherals
PRJ-2021-0044
Borrowable
New: IsBorrowable checkbox, default unchecked. Only items with this on appear in the picker in section 03.

Database change schema

DB Migration_Item_IsBorrowable.sql
IF NOT EXISTS (
    SELECT 1 FROM sys.columns
    WHERE object_id = OBJECT_ID('dbo.Item') AND name = 'IsBorrowable'
)
BEGIN
    ALTER TABLE dbo.Item ADD IsBorrowable BIT NOT NULL DEFAULT (0);
END

Default 0 is deliberate: existing items stay non-borrowable until someone opts them in, rather than the whole catalog suddenly appearing in the new picker.

Code changes

  • Item add/edit form under Pages/Item/ — bind a checkbox to IsBorrowable; optionally surface it as a column in the items grid.
  • Whatever repository backs Items Page CRUD — include IsBorrowable in the select/insert/update column lists.

Open decision: should a manually scanned/typed serial still resolve if IsBorrowable = 0? Recommended default is yes — the flag gates what's listed in the picker, not what a direct scan can find. If the team wants stricter enforcement, add the check to BorrowAsync instead and reject non-borrowable scans outright.
